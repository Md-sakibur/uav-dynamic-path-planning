# Experiment Notes: Dynamic UAV Path Planning

## Purpose

This note documents the initial batch experiment for the grid-based UAV dynamic-replanning prototype. It is intended to make the current observations reproducible and to distinguish implementation results from claims that have not yet been validated.

## Configuration

- Environment: 20 x 20 2D grid (default configuration)
- Occupancy generation: per-cell obstacle probability of 0.2
- Seeds: 42 through 61 (20 attempted scenarios)
- Planner: A* with Manhattan-distance heuristic
- Movement: four-connected, unit-cost grid moves
- Dynamic obstacle: a deterministic update along candidate cells from the initial route
- Metrics: success, initial and executed path length, planning calls, timed A* duration, replanning count, collision count, obstacle moves
- Commands:
  - `python -m experiments.run_experiments`
  - `python -m pytest -v`

## Recorded outcome

| Outcome | Count |
|---|---:|
| Scenarios attempted | 20 |
| Successful journeys | 15 |
| Scenarios without an initial route | 5 |
| Overall success rate | 75% |
| Collision counter among completed runs | 0 |

The seeds reported without initial routes were 43, 50, 51, 53, and 59. These cases failed before the moving-obstacle simulation began because A* could not find a route through the generated static map.

For the 15 completed scenarios, the reported executed path lengths were 40, 40, 42, 40, 48, 46, 44, 40, 38, 38, 42, 40, 40, 40, and 42 moves. The range was 38–48 moves, with an arithmetic mean of approximately 41.3 moves across these 15 completed runs.

A run using seed 42 reported an initial route of 38 moves and an executed route of 40 moves, with 40 replanning-loop calls, 34 obstacle moves, and zero counted collisions. These values describe that run only.

## Timing interpretation

The experiment records elapsed time around the explicit initial and per-step A* calls. Candidate-position checks used to select safe obstacle updates and the final route call for visualization are not included in the timing list. The timing values are therefore partial planner timings for this implementation and hardware, not an end-to-end simulation runtime or a real-time flight guarantee.

## Interpretation

The batch demonstrates that the current simulation can complete 15 of the 20 generated scenarios under the current controlled setup. Five maps had no initial path. Among the completed scenarios, the simulator recorded no collisions under its grid-level pre-movement check.

These observations do not prove collision avoidance for arbitrary obstacle movement, noisy observations, or physical UAVs. The simulated obstacle's candidate moves are screened so a route to the goal remains possible, and the environment state is directly available to the planner. The current experiment is therefore an initial benchmark rather than a rigorous comparison of planning algorithms.

## Recommended follow-up

1. Compare against Dijkstra or another baseline using the same maps and seeds.
2. Add more seeds and vary grid size and obstacle probability.
3. Add tests for no-initial-path cases and dynamic simulation invariants.
4. Make obstacle motion independent of the initial route to avoid overly favorable scenario selection.
5. Add observation uncertainty and explicit tracking/prediction only after defining measurable models and baselines.
